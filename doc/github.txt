INTRODUCTION                          *github* *github.nvim* *github-introduction*

github.nvim is a Lua port of denops-gh.vim for Neovim. It operates on
GitHub Issues, pull request lists, comments, and Projects v2 boards in
virtual buffers and uses the GitHub CLI for all GitHub API requests and
authentication.

Repository: https://github.com/skanehira/github.nvim
Original:   https://github.com/skanehira/denops-gh.vim

Public URI names use github://. Existing gh Plug mapping names are retained
for custom mappings; see |github-key-mappings|. Completion is outside the
current scope. The supported commands and buffer URIs are documented below;
TODO interfaces in the original plugin are not advertised as implemented.

==============================================================================
SETUP                                                         *github-setup*

Requires Neovim 0.10.4 or later, Git, and the GitHub CLI (gh). Authenticate gh
for github.com before operating on GitHub:
>
    gh auth login --hostname github.com
<
With lazy.nvim:
>lua
    {
      "skanehira/github.nvim",
      lazy = false,
      opts = {},
    }
<
The plugin also works without a plugin manager when its directory is on
'runtimepath' and its plugin files are loaded. Initialization does not invoke
gh or access GitHub. The optional Lua setup accepts nil, an empty table, or
the Projects settings:
>lua
    require("github").setup({
      projects = {
        group_by = "Status",
        column_width = 36,
        max_items = 1000,
      },
    })
<
`projects` accepts `group_by` (default `Status`), `column_width` (20-80,
default 36; used as the minimum width and widened to fill the board), and
`max_items` (1-10000, default 1000). Other keys, unknown
keys in `projects`, and invalid types or values are rejected without
applying part of the settings. See |github-projects| for the Project
commands and keys. Run |:checkhealth| with `github` to check the gh
executable and gh authentication:
>
    :checkhealth github
<
Manual loading for a temporary session:
>
    nvim -u NONE \
      --cmd 'set runtimepath^=/absolute/path/to/github.nvim' \
      -c 'runtime plugin/github.lua' \
      -c 'runtime plugin/github_related_pr.lua' \
      -c 'GitHub issues owner/repo'
<
Plugin managers normally generate help tags. For a manual checkout, run:
>
    :helptags /absolute/path/to/github.nvim/doc
    :help github
<

ISSUE WORKFLOW                                             *github-workflow*

1. Open the current checkout's Issues, or specify a repository:
>
    :GitHub issues
    :GitHub issues owner/repo
<
2. Use `ghs` to search. The one-line search buffer contains the last successful
   condition. Replace `state:open` with `state:closed` to see closed Issues.
   Enter applies the condition; q in Normal mode or CTRL-C cancels. Empty or
   unchanged conditions do not start another request.
3. Press K to preview the current row. A shared Markdown window opens while
   the cursor remains in the list. Repeated K updates that window. Move to the
   preview and press q to close it.
4. Use `ghe` to edit the body, `ght` for the title, and `ghm` for comments.
   Body, comment, and attribute navigation offers edit/new/vnew/tabnew, so the
   destination can use the current window, a split, a vertical split, or a tab.
5. Save an editing buffer with |:write|. Failed saves retain the text. Edits
   made while a save is running remain modified and are not included in that
   request. An existing body or attribute buffer with no changes is not sent.

Issue list rows use the following columns, aligned by display width:
>
    #12 Fix rendering OPEN   @alice @bob (bug, ui)   8
    #25 日本語の修正  CLOSED @alice      (feature)   0
<
The title is shortened after 100 display cells, followed by `...`; the first
two assignees and first three labels are shown. These are display limits:
editing and previews retain complete data. The final number is GitHub's total
comment count. A font containing the comment icon improves its appearance.

The comment list aligns `@author` and the first line of the body. Deleted
authors are displayed as `[deleted]`. K displays the full body.

Selection: CTRL-J or CTRL-K toggles the current row and then moves to the next
or previous row. A `*` marks selected rows. At the list edges the cursor stays
on the same row. With no selection, an operation uses the cursor row. Copy and
browser operations use the selected rows in list order, then clear selection.
Starting a refresh also clears selection, including when the refresh fails.
Body and comment editing require the selection to be cleared first.

Create an Issue with `ghn` from the Issue list or open the new-Issue URI.
Choose a Markdown template or Blank, edit the body, and use |:write| to open
`gh issue create` in a terminal. gh prompts for the title and other options.
After creation, choose Edit, Copy URL, Open in browser, or Done. Cancellation,
failure, or an unknown result retains the draft. If gh exits unsuccessfully
with a created-Issue URL, check GitHub before retrying. Requests are not retried
automatically. The list's `ghn` opens a horizontal split.

Create comments with `ghn` from the comment list. |:write| posts the text.
A successful post closes the draft unless it has later, unsent edits.
Title editing opens a one-line window and closes after successful saving;
later edits made during saving remain open and modified.

BUFFERS                                                     *github-buffers*

All public virtual buffers use `github://`. The corresponding
`https://github.com/owner/repo/issues...` URLs are also accepted. Identifiers
must be valid for the operation; a comment ID is its numeric database ID.

Every URI in the table below can omit `{owner}/{repo}/`, for example
`github://issues`, `github://pulls`, `github://issues/new`, or
`github://issues/{number}/comments`. When opened, the current cwd's Git origin
is resolved, then every window showing the buffer is replaced with the same
form under `github://{owner}/{repo}/`. The buffer is read-only until it is
replaced. If you leave the buffer before the origin is resolved, nothing else
happens. If resolution fails, an error is shown and the empty read-only buffer
stays open; run |:edit| to retry. HTTPS URLs cannot omit the repository.

URI                                                          Action
----------------------------------------------------------------------------
github://{owner}/{repo}/issues                                Issue list
github://{owner}/{repo}/pulls                                 PR list
github://{owner}/{repo}/issues/new                            Create Issue
github://{owner}/{repo}/issues/{number}                       Edit Issue body
github://{owner}/{repo}/issues/{number}/assignees             Edit assignees
github://{owner}/{repo}/issues/{number}/labels                Edit labels
github://{owner}/{repo}/issues/{number}/comments              Comment list
github://{owner}/{repo}/issues/{number}/comments/new          Post comment
github://{owner}/{repo}/issues/{number}/comments/{id}         Edit comment

Assignees and labels are edited one name per line. Saving replaces only that
attribute; an empty buffer clears it. The complete current set and required
candidates are fetched, including internal pagination, before replacement.
Invalid or unavailable names keep the input and prevent the update.

Targets are captured when the operation starts. Switching cwd, windows, or
repositories while a request runs does not redirect it. Old responses are
ignored after a newer request or when the owning buffer is unloaded.


ISSUE LIST                                        *github-buffer-issue-list*

github://issues
github://{owner}/{repo}/issues
    Open the repository's Issues with the initial condition state:open.
    At most 30 Issues are shown in GitHub's returned order. The columns are
    number, title, state, assignees, labels, and total comments; see
    |github-workflow| for display limits and selection behavior.

    Use |<Plug>(gh:issue:search)| to change conditions and
    |<Plug>(gh:issue:preview)| to inspect the current row. Other available
    actions are listed in |github-default-key-mappings|. Use |:edit!| to
    reload with the last successful condition. A failed refresh retains the
    previous successful result; an empty result displays "0 issues".

    Filetype: gh-issues

ISSUE SEARCH                                    *github-buffer-issue-search*

github:issues-search
    A one-line buffer opened by ghs from an Issue list. Its initial contents
    are the last successful search condition. For example:
>
    state:closed label:bug
<
    Enter in Insert or Normal mode confirms the condition, closes the search
    view, and returns to the invoking list window. Normal-mode q or CTRL-C
    in either mode cancels. Empty input or a condition equal to the latest
    successful condition does not send a request.

    Searches remain restricted to the repository of the invoking list. When
    the same list is displayed in multiple windows, the most recent caller
    owns the return window. Reopening its search preserves text being edited.

    Filetype: issue-search
    User event: gh_open_issue_search

ISSUE BODY                                        *github-buffer-issue-edit*

github://{owner}/{repo}/issues/{number}
    Read the Issue body into a Markdown editing buffer. |:write| updates only
    the body; an empty body is allowed. A buffer with no changes is not sent.
    CRLF text is normalized to LF. Unsaved edits are retained on read or save
    failure, and edits made after a save starts remain unsent and modified.

    ght opens |github-buffer-issue-title|. gha, ghl, and ghm open the same
    Issue's assignees, labels, and comments. Their destination menu offers
    edit, new, vnew, and tabnew. Menus use |vim.ui.select()|.

    Filetype: markdown
    User event: gh_open_issue

ISSUE TITLE                                      *github-buffer-issue-title*

    ght opens a one-line split for the current Issue's title. |:write| sends
    only the title and requires one nonblank line. Successful saving closes
    the title buffer, except when later edits remain unsent. Each Issue has
    its own title buffer, so editing another Issue does not replace a draft.

NEW ISSUE                                          *github-buffer-issue-new*

github://{owner}/{repo}/issues/new
    Choose one of the repository's Markdown templates, or Blank at the end
    of the menu, then edit its body. |:write| opens a terminal running
    gh issue create for this repository, with the saved body in a temporary
    file. Enter the title and other options in gh's interactive terminal.

    The Issue list's ghn opens a horizontal split, keeping the list visible.
    Repeated writes during creation do not launch another terminal. On
    success, choose Edit, Copy URL, Open in browser, or Done. The original
    draft closes only if it has no edits made after submission.

    Cancellation, failure, or an unknown result retains the draft. gh can
    exit unsuccessfully after creating an Issue; if a URL is reported or the
    result is unknown, check GitHub before retrying. The plugin never retries
    creation automatically.

    Filetype: markdown
    User event: gh_open_issue (after template selection)

ISSUE ASSIGNEES                           *github-buffer-issue-assignee-list*

github://{owner}/{repo}/issues/{number}/assignees
    Read all current assignees. Enter one GitHub login per line and save with
    |:write|. Saving replaces only the assignees; an empty buffer clears all.
    Logins are matched without case sensitivity and duplicates are removed.
    At most 10 distinct users may be assigned. Invalid/unavailable users or
    incomplete pagination prevent the update and preserve the input.

    A buffer with no changes is not sent. See |github-buffer-issue-label-list|
    for label editing; the two fields are saved independently.

    Filetype: gh-issues-assignees
    User event: gh_open_issue_assignees

ISSUE LABELS                                 *github-buffer-issue-label-list*

github://{owner}/{repo}/issues/{number}/labels
    Read all current labels, using internal pagination. Enter one complete
    label name per line and save with |:write|. Names containing spaces are
    kept as one label. Saving replaces only labels; an empty buffer clears
    all. Invalid/unavailable names prevent the update and preserve the input.
    A buffer with no changes is not sent.

    All label pages must be fetched before replacement is allowed. This
    prevents saving a partial set as if it were the complete attribute.

    User event: gh_open_issue_labels

COMMENT LIST                              *github-buffer-issue-comment-list*

github://{owner}/{repo}/issues/{number}/comments
    Display at most 100 comments. Rows align the @author and the body's first
    line. A deleted author is shown as [deleted]. Use K for the complete body,
    ghn to post, ghe to edit, ghy to copy URLs, and CTRL-O to open a browser.
    Selection uses CTRL-J and CTRL-K, as on the Issue list.

    Use |:edit!| to fetch the current comments again. A failed refresh retains
    the existing result; an empty result displays "0 comments".

    Filetype: gh-issues-comments

NEW COMMENT                                *github-buffer-issue-comment-new*

github://{owner}/{repo}/issues/{number}/comments/new
    Edit a Markdown draft and use |:write| to post it. Blank or whitespace-only
    text is rejected. Saving captures the body at that moment; repeated
    writes while posting do not submit another request.

    A successful post refreshes its originating comment list, when available,
    and closes the draft unless later edits remain. Failure or an unknown
    result preserves the draft and does not trigger an automatic retry.

    Filetype: markdown
    User event: gh_open_issue_comment

EDIT COMMENT                              *github-buffer-issue-comment-edit*

github://{owner}/{repo}/issues/{number}/comments/{id}
    Read and edit the comment body. {id} is the numeric comment database ID,
    not the Issue number. The comment must belong to the specified Issue.
    |:write| updates only the body. Blank/whitespace-only text is rejected;
    unchanged text is not sent. CRLF is normalized to LF when reading.

    Permission errors, deleted comments, and unknown results preserve input.
    Edits made during saving remain unsent and modified. The buffer remains
    open after successful editing.

    Filetype: markdown
    User event: gh_open_issue_comment

PREVIEW                                              *github-buffer-preview*

github:preview
    K on an Issue or comment list reuses a shared Markdown preview window in
    the current tab. Focus stays in the invoking list. Repeating K updates
    this view instead of opening another split. Move to it and press q to
    wipe the preview buffer.

    The preview uses the list's fetched body, which may be older than GitHub.
    Reload the list with |:edit!| to fetch current content. Previewing does not
    send another request and does not edit the body.

    Filetype: markdown

PULL REQUEST LIST                                    *github-buffer-pull-list*

    :GitHub pulls
    :GitHub pulls owner/repo
    :edit github://pulls
    :edit github://owner/repo/pulls
    :edit https://github.com/owner/repo/pulls

    Show up to 30 open PRs. Columns match the Issue list: number, title, state,
    assignees, labels, and conversation comment count (excluding review-line
    comments). MERGED is displayed separately from CLOSED.

    Press ghs to search; use state:closed for closed PRs or is:merged for merged
    PRs. The search buffer has the same Enter/q/<C-c> behavior as Issue search.
    K previews the full body. <C-j>/<C-k> select rows, ghy copies URLs, and
    <C-o> opens URLs in a browser. Selection clears after URL operations.
    Reload with :edit!. PR editing, creation, merging, and review operations
    are not provided. The filetype is gh-pulls.

PROJECTS                                                     *github-projects*

Projects v2 boards are displayed in floating windows. Projects have no
github:// URI and no HTTPS entry. Only github.com is supported. gh must be
installed and authenticated; some Projects operations also require the
`project` scope. Missing preparation is reported without opening a window.

COMMANDS

:GitHub projects [owner] [number]
    Open the Project list for owner, or the board of a Project when
    number is given. Without owner, the authenticated user is used.
    `@me` also means the authenticated user. When the first argument is
    numeric, it is a Project number and owner is the authenticated user.
    Projects work outside a Git checkout because they belong to a user
    or an organization, not to a repository.
>
    :GitHub projects
    :GitHub projects skanehira
    :GitHub projects skanehira 12
    :GitHub projects 12
<
    Invalid arguments, such as too many arguments, an empty owner, an
    owner containing `/` or characters other than letters, digits, and
    hyphens, or a number that is not a positive integer, show
    `Usage: GitHub projects [owner] [number]` and open no window.

PROJECT LIST

    The header shows `Projects for <owner> (<type>)  ·  <count> open`.
    Rows show `#<number> <title>  <items> items  <public|private>`, with
    long titles shortened by display width. Loading shows
    `Loading projects...`; failure shows `Error: <reason>`. An empty list
    shows `No open projects`. When 100 open Projects are shown and more
    remain, `Showing 100 projects` is displayed. Closed Projects are not
    listed.

    j and k select the previous or next Project; <CR> opens the board;
    r reloads the list; q or <Esc> closes the list and its board. A
    reload keeps the selection by Project number and clamps it when that
    Project is gone. A reload failure keeps the previous list and shows
    the reason. Opening the same owner again reuses the list window and
    reloads it.

Project list:
    Key       Action
    ------------------------------------------------------------------------
    j / k     Select the previous / next Project
    <CR>      Open the selected Project board
    r         Reload the list
    q / <Esc> Close the list

PROJECT BOARD

    The header shows `<owner> / <title>  ·  <items> items  ·  filter:
    <filter>`. When the filter comes from the Project's first view, it
    shows `view: <name>  ·  filter: <filter>`. Loading shows
    `Loading <fetched>/<total>...`; truncation shows
    `Showing <max_items> of <total>`; failure shows `Error: <reason>`.

    Columns follow the options of the single-select field chosen by
    `group_by`; items without a value go to the last `○ 値なし` column.
    Column headers show `● <name> <count>` in the option color and a `+`
    at the right edge. Cards use a rounded border and GitHub-like label
    chips, assignee avatars, sub-Issue progress, and related PRs. Issue
    and PR titles wrap to as many lines as needed instead of being
    truncated; the card height grows with the title. Draft Issues show
    their title; unavailable items show `[redacted]`. Columns use
    `column_width` as a minimum and widen to fill the board; they scroll
    horizontally when they do not fit. Each column keeps its own vertical
    position.
    Resizing the editor repositions the list and board and keeps the
    selection and column positions.

    h and l move between columns; j and k move between items in the
    selected column; H and L move to the first or last column; g and G
    move to the first or last item. Movement stops at the edges and does
    not move within an empty column. Opening the same Project again
    reuses its board window and reloads it.

Project board:
    Key       Action
    ------------------------------------------------------------------------
    h / l     Previous / next column
    j / k     Previous / next item in the selected column
    H / L     First / last column
    g / G     First / last item in the selected column
    K         Preview the selected item body
    <CR>      Open an Issue, PR, or draft Issue
    <C-o>     Open the item URL in a browser
    ghy       Copy the item URL to the + register
    ghs       Change the Project filter
    ghe       Edit the selected item's fields
    ghn       Add an existing Issue/PR or a draft Issue
    ghd       Delete the selected item from the Project
    r         Reload the board
    ?         Show key help
    q / <Esc> Close the board and its child windows

    K opens a Markdown preview of the selected item; j, k, gg, G, <C-d>,
    and <C-u> scroll it; q or <Esc> closes only the preview. <CR> opens
    an Issue in a new tab as `github://<owner>/<repo>/issues/<number>`,
    a PR in the browser, and a draft Issue in the preview. A redacted
    item cannot be previewed, moved, or opened. <C-o> opens an Issue or
    PR URL in the browser, and ghy writes it to the + register. Draft
    and redacted items report that they have no URL. Browser and
    clipboard failures are reported; an unconfirmed clipboard result is
    not reported as success.

    ghs opens a one-line filter with the current filter as its initial
    value. Enter applies it; q or <C-c> cancels. An empty filter shows
    all items; an unchanged filter does not reload. A filter that
    matches no items is a successful empty result. A failed reload keeps
    the previous items and filter. r reloads the same Project and filter
    and keeps the selection by item ID. ? opens the key help for the
    list, board, field editing, and add/delete screens and keeps the
    board; j, k, gg, and G scroll the help. q or <Esc> closes the
    board and its child windows, returning to the Project list when the
    board was opened from it, or to the original window.

FIELD EDITING

    ghe lists the selected item's editable fields. Editable fields are
    custom single-select, text, number, and date fields; built-in fields
    such as Title, Assignees, and Labels are not listed and remain
    available through the Issue operations. Each row shows
    `<name>  <current value>`, or `未設定` when the field has no value.
    When there are no editable fields, `No editable fields` is shown and
    the window stays open. Selecting a column header or an empty column
    reports that an item must be selected and opens no editor. Opening
    ghe again on the same board reuses the editor and updates it for the
    selected item.

    j and k select a field; <CR> edits it; q or <Esc> closes the field
    editor and returns to the board. The editor is a child of the board,
    so closing the board closes it and its child windows.

Field editor:
    Key       Action
    ------------------------------------------------------------------------
    j / k     Select the previous / next field
    <CR>      Edit the selected field
    q / <Esc> Close the field editor

    A single-select field opens its options. Each option shows
    `● <name>`, the current value is marked, and the options end with
    `値を解除` to clear the value.
    j and k select an option; <CR> applies it or clears the value; q or
    <Esc> cancels and returns to the field editor. Applying the same
    value sends no update and closes the options. A failed update keeps
    the options open and the selection, and does not change the board.

Single-select options:
    Key       Action
    ------------------------------------------------------------------------
    j / k     Select the previous / next option
    <CR>      Apply the option, or clear the value
    q / <Esc> Cancel and return to the field editor

    A text, number, or date field opens a one-line input with the
    current value. The field name and type are shown as the border
    title. Enter applies the value; <C-c> cancels. In Normal mode, q
    cancels. An empty input clears the field. A number must be a finite
    number; a date must be a real `YYYY-MM-DD` date between 0001 and
    9999. Invalid input is not sent and keeps the input with a reason.
    A failed update keeps the input and does not change the board.

One-line input:
    Key       Action
    ------------------------------------------------------------------------
    <CR>      Apply the value
    <C-c>     Cancel
    q         Cancel in Normal mode

    An update sends only the selected field and never rewinds other
    fields. The response updates the field editor and the local board;
    no automatic reload or resend follows. A change to the group field
    moves the item to its new column; other single-select changes keep
    the item in its column. The selection is kept by item ID.

ADDING AND DELETING ITEMS

    ghn opens a choice between `既存のIssue/PR` and `下書きIssue`.
    j and k select an entry; <CR> continues; q or <Esc> cancels. The
    choice is available even when a column header is selected, and the
    item is added to the same Project.

Add choice:
    Key       Action
    ------------------------------------------------------------------------
    j / k     Select the previous / next entry
    <CR>      Continue
    q / <Esc> Cancel and return to the board

Existing item input:
    Key       Action
    ------------------------------------------------------------------------
    <CR>      Add the item
    <C-c>     Cancel
    q         Cancel in Normal mode

    For an existing item, enter a URL or `owner/repo#number` at the
    `Issue/PR URL or owner/repo#number` prompt. These forms are
    accepted:
>
    https://github.com/<owner>/<repo>/issues/<number>
    https://github.com/<owner>/<repo>/pull/<number>
    <owner>/<repo>#<number>
<
    A trailing `/` is accepted; query strings, fragments, and extra path
    segments are rejected. Enter adds the item; <C-c> cancels. Invalid
    input, an unresolved Issue/PR, and failures keep the input and show
    the reason. Adding an item that is already in the Project returns
    the existing item and reports that no duplicate was created.
    Temporary conflicts show the reason and accept another attempt. The
    added item is selected at the end of its column. When the current
    filter does not match it, the board does not show it and reports
    that the filter must be cleared. Adding is idempotent, so a retry
    does not create duplicates.

Draft title:
    Key       Action
    ------------------------------------------------------------------------
    <CR>      Continue to the body
    <C-c>     Cancel the flow
    q         Cancel in Normal mode

Draft body:
    Key       Action
    ------------------------------------------------------------------------
    <C-s>     Add the draft Issue
    q / <Esc> Close the body and return to the title

    For a draft Issue, enter a title (`Draft title`); Enter moves to the
    body and <C-c> cancels the flow. A title that is empty or only
    whitespace is not sent and keeps the title input with a reason. The
    body is a Markdown buffer with the prompt
    `Draft body (C-s to add, q/Esc to cancel)`; <C-s> adds the draft,
    and q or <Esc> closes only the body and returns to the title. The
    body may be empty. A failure keeps the body and input. Each draft
    creates a new item, so duplicates are not checked.

    ghd opens a confirmation for the selected item:
>
    Delete this item from the project?
    Issue #12 Fix the title
    y: delete  n/q/Esc: cancel
<
    The second line shows the item's type, number, and title; a
    redacted item shows `[redacted]`. y deletes the item; n, q, or
    <Esc> cancels. Deletion removes only the item from the Project; the
    Issue or PR itself is not deleted. A failure keeps the confirmation
    open and accepts another y or a cancel. An item that is already
    gone is not reported as deleted; the board is kept and r reloads
    it. After deletion, the selection moves to the next item, then the
    previous item, then the column header. A redacted item can be
    deleted, but it cannot be previewed, moved, or opened.

Delete confirmation:
    Key       Action
    ------------------------------------------------------------------------
    y         Delete the item from the Project
    n / q / <Esc> Cancel

SETTINGS

    |github-setup| documents `projects` in require("github").setup().
    `group_by` selects the single-select field used for columns (default
    `Status`); when it does not match, the first single-select field is
    used, and without one the board has a single column. `column_width`
    sets the minimum column width (20-80, default 36); columns are
    widened to fill the board. `max_items` limits fetched
    items (1-10000, default 1000). New values apply from the next fetch
    or redraw; existing float windows are not closed. See |github-limits|
    for the Projects limits.

KEY MAPPINGS                 *github-key-mappings* *github-default-key-mappings*

Mappings are buffer-local and use the original gh Plug names for custom keys.
All defaults below are Normal-mode mappings.

Issue list:
    Key       Plug                                      Action
    ------------------------------------------------------------------------
    ghe       *<Plug>(gh:issue:edit)*                      Edit body
    ght       *<Plug>(gh:issue:edit:title)*                Edit title
    ghn       *<Plug>(gh:issue:new)*                       Create Issue
    gho       *<Plug>(gh:issue:open)*                      Reopen
    ghc       *<Plug>(gh:issue:close)*                     Close

COMMANDS                                                    *github-commands*

:GitHub {issues|pulls} [owner/repo]                              *:GitHub*
    Open an Issue or pull request list in the current window. Without a
    repository argument, resolve the current cwd's Git origin. Explicit
    owner/repo works without a local checkout. Only github.com is supported.
    Invalid arguments or origin failures are reported without opening a list.
    If the source window/buffer changes or you edit while origin lookup is
    pending, its delayed result does not replace your work. Starting another
    GitHub command supersedes a pending list-opening command.
>
    :GitHub issues
    :GitHub pulls
    :GitHub issues skanehira/github.nvim
    :GitHub pulls skanehira/github.nvim
<
:GitHub projects [owner] [number]
    Open the Project list for owner, or the board of a Project. Without
    owner, the authenticated user is used. `@me` also means the
    authenticated user. A numeric first argument is a Project number.
    Projects are shown in float windows and have no github:// URI; see
    |github-projects|.
>
    :GitHub projects
    :GitHub projects skanehira
    :GitHub projects skanehira 12
    :GitHub projects 12
<
:GitHub related-pr {commit}
:GitHub related-pr {owner/repo} {commit}
    Display the first PR associated with a commit. The first form resolves
    the current checkout's origin; the second works without a checkout.
>
    :GitHub related-pr HEAD
    :GitHub related-pr skanehira/github.nvim HEAD
<
:GhGetAssociatedPullRequest {commit}                  *:GhGetAssociatedPullRequest*
    Compatibility alias for :GitHub related-pr.
    Display the first PR associated with a commit. The repository is resolved
    from the Git origin at the cwd captured when the command is run.

:GhGetAssociatedPullRequest {owner} {repo} {commit}
    Display the first associated PR from the explicit repository. This form
    does not require a local Git checkout. No associated PR and request

LIMITS                                                       *github-limits*

- Only github.com is supported in this release.
- Search displays at most 30 Issues or PRs; comments display at most 100 entries.
  There is no list page navigation. Assignee/label pagination is internal and
  independent of these display limits.
- GitHub communication uses gh. Tokens and gh authentication files are managed
  by gh and are not read directly by the plugin.
- Clipboard operations write URLs to the `+` register, separated by LF without
  an extra trailing line. Neovim does not reliably expose provider completion;
  the plugin reports the requested count and an unconfirmed result rather than
  claiming success. Detectable failures, such as no provider, are reported.
- Saving the same field from multiple clients follows GitHub's last accepted
  update. Each request changes only the selected field.
- Completion, Actions, PR reviews, Gists, repository-file browsing, and README
  buffers are not implemented. Actions and review integration are future work.
- Projects are float-window screens without github:// URIs or HTTPS entries.
  They require gh authentication, and some operations also require the
  `project` scope. Missing preparation is reported without opening a window.
  Opening a closed Project by number reports that it is closed and opens no
  board.
- Project lists show at most 100 open Projects without page navigation;
  closed Projects are not listed. Fields are limited to the first 50 and
  views to the first 10. Items are fetched 100 per page up to `max_items`
  (default 1000), and truncation is displayed. Reload with r to fetch again.
- Project views are not switched or saved; the lowest-numbered view's filter
  is the initial filter. Item reordering, archiving, multi-select and
  iteration editing, creating or editing Projects and fields, and editing a
  draft Issue's title or body after creation are not provided. Projects
  expose no <Plug> mappings and do not support mouse operations. Each tab
  manages its own Project windows; screens in another tab are not operated
  on.
- Project filters are evaluated by GitHub. An invalid filter may return no
  items instead of an error; zero items is shown as a successful result and
  the filter syntax is not validated.
- Project writes update the local board from the mutation response and do
  not reload or resend automatically. Reads immediately after a write can be
  stale for about 0-3 seconds; r is authoritative. An update sends only the
  selected field. Concurrent edits follow GitHub's last accepted update.
- Built-in Project fields (Title, Assignees, Labels, and others) are edited
  through the existing Issue operations, not the field editor. Items whose
  content cannot be read are shown as [redacted]; they can be deleted from
  the Project but cannot be previewed, moved, or opened. Draft Issues have
  no URL.

FAQ                                                            *github-faq*

How do I show closed Issues?
    Open an Issue list, press ghs, replace state:open with state:closed, and
    press Enter. Add qualifiers such as label:bug to narrow the search.

Why do gh-issues or gh_open_issue still contain "gh"?
    Filetypes, User events, and Plug mappings retain the original names for
    existing customizations. The public URI scheme is github://.

How do I reload or inspect newer content?
    Use :edit! on a list to fetch it again, then K for the refreshed preview.
    For an editing buffer, :edit! can discard unsaved changes; preserve any
    draft you want before requesting a reload.

Why do URLs report "result unconfirmed" after copying?
    Neovim can return before the clipboard provider reports completion or
    failure. The plugin writes to the + register but does not claim success
    without confirmation. Check |:checkhealth| if the provider is unavailable.

Where are completion settings, Actions, or PR review?
    They are not implemented in this release. Completion was excluded from
    the port; Actions and review integration are future work. See
    |github-limits|. The original plugin's TODO-only interfaces are also not
    supported here.
