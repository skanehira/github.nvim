filter_matchが既知の不一致termを先に見つけると即falseを返すため、同じフィルタに未知の修飾子が含まれていても『一致しない』と断定する。設計projects-item-manage.md:62は未知の修飾子を含む場合に一致を断定せずフィルタ解除を案内するとしており、案内文が誤って『does not match』になる。

evidence
コード: item_manage.lua:326-348のfilter_matchは各termを順に評価し、`if matched == false then return false`（:338-339）で未知termの追跡（unknown）より先に確定する。例: フィルタ`status:Done has:label`でstatusがTodoの項目は、status:Doneのfalseで即falseになり、has:labelのunknown（term_matchesのelse分岐が:306-318でnil）を無視する。設計: projects-item-manage.md:62。テスト: item_manage_spec.lua:992-1016は引用符だけで、未知の修飾子（has:label等）と既知falseの混在を固定していない。
fix_hint
全termを評価してfalseとunknownを集計し、unknownが1つでもあればnilを返す（falseよりunknownを優先）。`status:Done has:label`のような混在フィルタのテストを追加し、案内がADD_FILTER_UNKNOWNになることを固定する。
