# Issueの一覧・検索・プレビュー

- 種別: 機能設計書
- 対象 UC: UC-002 (docs/design/USECASES.md)

## 何を作るか

UC-002の利用者操作を実現する。対象規則はBR-006, BR-007, BR-008, BR-009, BR-010, BR-011, BR-012, BR-013。認証・実行・リポジトリ文脈と非同期の共通規約はDESIGN.md「横断規約」に従う。

## 入出力と振る舞い

- `github://owner/repo/issues`と対応するHTTPS URLから一覧を開く。bufferごとにhost/owner/repo、最後に成功した検索条件、表示行とIssueの対応、各IssueのGraphQL node ID、選択、要求世代を保持する。状態変更時は行に対応するIDを状態変更機能へ渡す。IDを取得できないIssueは状態変更の際に対象ごとに理由を報告し、そのIssueへの更新を送らない。
- 初回の`state:open`は最大30件。番号・タイトル・状態・担当者・ラベル・コメント総数を表示し、GitHub検索の返却順を保つ。コメント総数は取得したコメント配列の長さではなくtotalCountを使う。
- `<C-j>`/`<C-k>`はカーソル行の選択印をトグルして次/前行へ移動する。端では移動せず、行がない場合は何もしない。一覧の再取得を開始すると選択を解除する。
- `ghs`で条件を編集してEnterで検索する。再読込は成功済み条件を使う。`K`はカーソル行の取得済み本文を縦分割表示する。0件は以前の行を消して0件と表示する。
- repo変更を含む検索条件が別repoの結果を混入させないよう、返されたrepository identityを照合し、不一致なら結果全体を採用せず理由を通知する。cwdが変わっても一覧を開いた時の対象を使う。

正常系の操作:

| # | アクター | アクション |
| --- | --- | --- |
| 1 | 開発者 | `:edit github://owner/repo/issues`でIssue一覧を開く。 |
| 2 | github.nvim | 対象リポジトリと初期検索条件`state:open`を、その一覧の条件として保持する。 |
| 3 | github.nvim | ghを使って条件に一致するIssueを最大30件取得する。 |
| 4 | github.nvim | 各Issueの番号・タイトル・状態・担当者・ラベル・コメント総数を表示する。 |
| 5 | 開発者 | `ghs`で検索欄を開き、条件を入力してEnterで確定する。 |
| 6 | github.nvim | 同じリポジトリ内を検索し、操作した一覧の条件と結果を更新する。 |
| 7 | 開発者 | 確認したいIssueへカーソルを移動し、`K`を押す。 |
| 8 | github.nvim | カーソル行の取得済み本文を、一覧を残した縦分割の窓に表示する。 |

#### E: 検索条件の入力をキャンセルする（ステップ5）

| # | アクター | アクション |
| --- | --- | --- |
| 5a | 開発者 | 検索欄を確定せずにキャンセルする。 |
| 5b | github.nvim | 新しい検索を開始せず、直前の成功結果と検索条件を保持する。 |

例外フロー:

#### E1: 検索・取得に失敗する（ステップ3・6）

| # | アクター | アクション |
| --- | --- | --- |

| # | アクター | アクション |
| --- | --- | --- |
| 3a | 開発者 | 先の検索の完了前に条件を変えて再検索するか、対象の一覧を閉じる。 |
| 3b | GitHub | 先の検索の応答を返す。 |
| 3c | github.nvim | 先の応答で新しい検索結果や別の画面を上書きしない。閉じた一覧を応答によって再作成しない。 |

## API

GraphQL `search(first:30,type:ISSUE,query:...)`で`repo:<owner>/<repo> type:issue`と検索条件を使い、各Issueのrepository、id、number、title、state、body、comments.totalCount、assignees、labels、URLを取得する。件数制限で担当者・ラベルが欠ける場合は接続をページングする。共通契約はDESIGN.md「GitHub API一覧」参照。

## エッジケースの決定

- 空: 初回や検索で0件なら0件を表示する。
- 境界: 最大30件。画面のページ送りは対象外。
- エラー: 初回失敗は理由を表示し、再検索失敗では直前の成功結果と条件を維持する。
- 並行: 同じbufferの新しい要求を優先し、閉鎖後や別bufferに古い応答を適用しない。
- 再表示: 同じ一覧の再読込は最後に成功した検索条件と固定対象を使い、再取得開始時に選択を解除する。失敗時も選択は戻さない。

一覧の結合テストでは、foundationの`plugin/github.lua`を`runtime plugin/github.lua`で登録し、実際のURI入口を通す。setup機能の実装には依存しない。
