# Project項目の追加・削除

- 種別: 機能設計書
- 対象 UC: UC-017 (docs/design/USECASES.md)
- 対象ストーリー: US-023

## 何を作るか

UC-017の利用者操作を実現する。対象規則はBR-078〜BR-084。ボードの状態と描画はprojects-board、float UIの共通規則はprojects-ui、APIはprojects-apiに従う。

## 入出力と振る舞い

### 起動と状態

- ボードで`ghn`を実行すると、既存のIssue/PRを追加するか下書きIssueを作成するかを選ぶfloatを開く。空の列や列ヘッダを選んでいる場合も実行でき、追加先は同じProjectとする。
- 追加の流れは`{board, mode, step, input, title, body, error, generation, submitting}`を保持する。`mode`は`existing`または`draft`、`step`は`choice`、`existing`、`title`、`body`のいずれか。
- `ghd`は選択中の項目に対して確認floatを開く。空の列や列ヘッダを選んでいる場合は項目を選ぶよう案内し、確認を開かない。
- 同じボードで追加の流れや確認が既に開いている場合は、既存のfloatをフォーカスし、二重に開かない。
- 追加・削除の流れはボードの子画面とし、ボードを閉じるとすべての子画面を閉じる。追加成功時は流れの全画面を閉じ、削除成功時は確認を閉じる。

### 既存のIssue/PRの追加

- 選択画面は`既存のIssue/PR`と`下書きIssue`を表示する。`j`/`k`で選び、`<CR>`で次へ、`q`/`<Esc>`で中止する。
- 既存項目の入力は1行のfloatで、プロンプトに`Issue/PR URL or owner/repo#number`を表示する。`<CR>`で追加、`<C-c>`で中止する。入力は前後の空白を除く。
- 受け付ける形式は次のとおり。
  - `https://github.com/<owner>/<repo>/issues/<number>`
  - `https://github.com/<owner>/<repo>/pull/<number>`
  - `<owner>/<repo>#<number>`
- URLは末尾の`/`を許容し、query・fragment・余分なpathは拒否する。ownerは英数字とハイフン、repoは英数字・ハイフン・アンダースコア・ドットとし、`#`の後の番号は正の整数とする。
- 入力が空、形式が不正、owner/repoや番号が不正な場合は送信せず、理由を表示して入力と入力値を保持する。
- IssueとPRは番号を共有するため、GraphQL `repository(owner:, name:){ issueOrPullRequest(number:){ __typename ... on Issue { id } ... on PullRequest { id } } }`で1つのnodeを解決する。`__typename`でIssue/PRを判定する。nullなら`not_found`とする。`issue`と`pullRequest`を同時に問い合わせると非該当側がNOT_FOUNDになりクエリ全体が失敗するため、`issueOrPullRequest`を使う。
- `addProjectV2ItemById`を実行し、応答の`item`をボードのモデルへ追加する。送信中は`submitting=true`とし、`<CR>`の再操作を無視する。応答後に解除する。応答の項目が既にモデルにある場合は`duplicate=true`とし、重複を作らず既存項目を選択して案内する。モデルにない既存項目（フィルタ外・max_items外・アーカイブ済み）は、応答の項目を追加し、既存か新規かを断定しない旨を案内する。`r`で再取得して確認できる。
- 追加した項目は、応答のグループ値に対応する列の末尾に置く。グループ値がない場合は値なし列に置く。項目を選択してスクロールし、流れを閉じる。
- 一時的な競合エラーは理由を表示し、入力と流れを保持する。追加は冪等なので、利用者の再操作を受け付ける。自動で再送しない。
- 応答が不完全でグループ値が取れない場合は値なし列に置き、`r`で再取得するよう案内する。

### 下書きIssueの追加

- 選択画面で`下書きIssue`を選ぶと、タイトルの1行入力へ進む。プロンプトは`Draft title`とし、`<CR>`で本文へ、`<C-c>`で中止する。
- タイトルは前後の空白を除いて1文字以上とする。空白だけの場合は送信せず、理由を表示してタイトル入力を保持する。
- 本文は複数行のfloatで、`filetype=markdown`、プロンプトは`Draft body (C-s to add, q/Esc to cancel)`とする。`<C-s>`で追加、`q`/`<Esc>`で中止する。本文は空でもよい。
- 本文の`q`/`<Esc>`は本文画面だけを閉じ、タイトル入力へ戻る。タイトルの`<C-c>`は追加の流れを中止してボードへ戻る。
- `addProjectV2DraftIssue`を実行し、応答の`projectItem`をボードのモデルへ追加する。送信中は`submitting=true`とし、`<C-s>`の再操作を無視する。応答後に解除する。新しい下書きは値なし列の末尾に置き、項目を選択してスクロールし、流れを閉じる。本文は`body_cache`に保持する。
- 失敗した場合は理由を表示し、本文画面と入力値を保持する。タイトルは保持したまま再試行できる。自動で再送しない。
- 下書きの追加は毎回新しい項目を作るため、重複判定は行わない。

### 削除

- `ghd`は選択項目の確認floatを開く。1行目に`Delete this item from the project?`、2行目に項目の種別・番号・タイトル（redactedは`[redacted]`）、3行目に`y: delete  n/q/Esc: cancel`を表示する。
- `y`で`deleteProjectV2Item`を実行する。`n`/`q`/`<Esc>`で中止し、mutationを送らない。
- 送信中は`submitting=true`とし、二重送信を防ぐ。成功したらボードのモデルから項目を除き、確認を閉じる。
- 削除後の選択は同じ列の次の項目、なければ前の項目、なければ列ヘッダへ移す。`body_cache`から項目の本文を除く。ヘッダの件数を更新する。
- 削除はProjectから項目を外すだけで、Issue/PR自体を削除しない。成功時にその旨を案内する。
- 失敗したら確認を閉じず、理由を表示して`y`での再試行と`n`での中止を受け付ける。ボードのモデルは変更しない。自動で再送しない。
- 既に対象が存在しない場合は`not_found`として扱い、成功と断定しない。ボードの内容を保持し、`r`で再取得するよう案内する。
- redacted項目も削除できる。本文プレビュー・移動・URL操作はできないが、Projectから外す操作は許可する。

### ローカル状態と選択

- 追加・削除の成功時はmutationの応答でローカル状態を更新し、自動で再取得しない。`totalCount`を増減し、表示中の件数を再計算する。
- 追加した項目が現在のフィルタに一致しない場合、ボードの表示対象には加えず、追加成功とフィルタ解除の案内を表示する。`totalCount`は増やす。フィルタに一致する場合は列の末尾に表示して選択する。
- 削除した項目がフィルタで表示されていた場合は、同じ列の次の項目/前の項目/列ヘッダへ選択を移す。
- 追加・削除の後で`r`を実行すると再取得し、選択を項目IDで維持する。追加した項目が反映遅延で見つからない場合は同じ列の同じ位置へclampする。
- ボードを閉じた後や古い応答が届いた場合は、ボードや別の画面を更新しない。

### エラー

- 入力不正、Issue/PRの解決失敗、権限不足、認証不足、通信失敗、レート制限、結果不明を区別し、理由を表示する。
- 入力不正・解決失敗・権限不足・通信失敗では入力を保持する。追加の流れでは選択画面からやり直せる。
- 結果が不明な場合は成功と断定せず、入力または確認を保持し、`r`で確認するよう案内する。
- 追加は冪等であり、一時的な競合の後に再実行しても重複しない。削除は冪等ではないため、結果不明時に自動再送しない。
- ghが未導入・未認証、または`project`スコープがない場合は、不足する準備を案内し、流れを中止しない。認証後に再操作できる。

### 画面

- 選択画面は幅40%・高さ4、既存項目とタイトルの入力は幅50%・高さ1、本文は幅70%・高さ60%、確認は幅40%・高さ3とする。projects-uiの`target_size`と中央配置を使う。
- 選択画面はボードの子、既存項目・タイトルの入力は選択画面の子、本文はタイトル入力の子、確認はボードの子とする。
- 1行入力はボーダーのタイトルにプロンプトを表示し、`startinsert`で開始する。本文は`modifiable=true`、`filetype=markdown`とし、`<C-s>`を挿入モードと通常モードの両方に設定する。
- 選択行を強調し、カーソルを選択行に置く。確認の項目タイトルは表示幅で切り詰める。エラーは通知または確認のヘッダに表示する。

### 終了

- 選択画面の`q`/`<Esc>`はボードへ戻る。既存項目・タイトルの`<C-c>`は選択画面へ戻る。本文の`q`/`<Esc>`はタイトルへ戻る。
- 確認の`n`/`q`/`<Esc>`はボードへ戻る。
- ボードを閉じると追加・削除の全子画面を閉じる。ボードの`q`/`<Esc>`は子画面を閉じた後にボードを閉じる。

## API

`projects-api`のIssue/PR解決、項目の追加、下書きの追加、項目の削除を使う。

- Issue/PRの解決: `repository(owner:, name:){ issueOrPullRequest(number:){ __typename ... on Issue { id } ... on PullRequest { id } } }`
- 既存項目の追加: `addProjectV2ItemById(input:{projectId, contentId})`。応答の`item`から完全な項目を取る。
- 下書きの追加: `addProjectV2DraftIssue(input:{projectId, title, body})`。応答の`projectItem`から完全な項目を取る。
- 項目の削除: `deleteProjectV2Item(input:{projectId, itemId})`。応答の`deletedItemId`を確認する。

GraphQLの形と項目のフィールドはprojects-apiを参照する。mutationの応答が不完全な場合は、追加した項目を値なし列に置き、`r`で再取得する。ブラウザ・クリップボードは使わない。

## 実装の配置

| 処理 | 層 | 実装先ファイル |
| --- | --- | --- |
| 追加の選択・入力・下書き・確認・ローカル更新 | 機能 | `lua/github/features/projects/item_manage.lua` |
| 項目の追加・削除の振る舞いの検証 | テスト | `lua/github/features/projects/item_manage_spec.lua` |

ボードのモデル更新・列・選択・再描画はprojects-boardが提供するAPIを呼ぶ（`board.lua`は変更しない）。Issue/PR解決・追加・下書き・削除のmutationはprojects-api、float・入力・確認の共通UIはprojects-uiの子が実装する。本issueは`item_manage.lua`と`item_manage_spec.lua`を所有する。追加・削除はghを直接呼ばず、Projects API層を通す。テストではfake ghと`core/float.lua`を使い、実GitHubの書込みを行わない。`doc/github.txt`の`ghn`/`ghd`と入力のキー説明は実装issueで更新する。

## エッジケースの決定

- 入力: 空、空白、URLの末尾`/`、query/fragment、余分なpath、`owner/repo#number`の前後の空白、owner/repoの不正、番号0・負数・小数、IssueとPRの番号共有。
- 対象: Issue、PR、下書き、redacted、削除済み、権限なし、アクセスできない、存在しない。
- 追加: 重複、一時的な競合、応答の不完全、フィルタ不一致、`max_items`打ち切り、値なし列、列の末尾、選択とスクロール。
- 下書き: タイトルの空白のみ、本文空、本文複数行、日本語、長いタイトル、本文のキャンセル、タイトルのキャンセル。
- 削除: 確認の`y`/`n`/`q`/`<Esc>`、二重送信、削除済み、権限なし、redacted、選択の移動、最後の項目、空の列。
- エラー: 入力不正、解決失敗、認証不足、権限不足、通信失敗、レート制限、結果不明。
- 並行: 古い応答、閉じた画面、別画面の更新、別タブの画面。
- 画面: 小さい画面、リサイズ、既存の流れの再利用、ボードを閉じた場合。
