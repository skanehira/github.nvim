# Issue担当者・ラベル編集

- 種別: 機能設計書
- 対象 UC: UC-006 (docs/design/USECASES.md)

## 何を作るか

UC-006の利用者操作を実現する。対象規則はBR-028, BR-029, BR-030, BR-031。認証・実行・リポジトリ文脈と非同期の共通規約はDESIGN.md「横断規約」に従う。

## 入出力と振る舞い

- `gha`/`ghl`または対応URIでカーソル行の担当者・ラベルを1行1件で編集する。現在の集合は完全に取得してから表示し、途中ページ取得失敗時は不完全な集合を保存可能にしない。
- 空行を除き重複値を1件にして保存する。全行削除は対象項目の全解除。存在しないラベルや割当できないユーザーは理由を表示して入力を維持し、ラベルを暗黙作成しない。
- 検証後のID集合を対象項目だけに置換する。成功後にも追記があれば未保存として残す。

同一編集bufferの保存中に再度`:write`した場合は進行中と通知し、追加の保存要求を送らない。保存開始後の編集は未保存のまま残し、完了後に利用者が改めて保存できる。

正常系の操作:

| # | アクター | アクション |
| --- | --- | --- |
| 1 | 開発者 | カーソル行のIssueで`gha`または`ghl`を実行する。 |
| 2 | github.nvim | 担当者またはラベルの現在値を1行1件で表示する。 |
| 3 | 開発者 | 追加・削除・変更を行い、`:write`で保存する。 |
| 4 | github.nvim | 候補となる名前を検証し、入力した集合で対象項目を置換する。 |
| 5 | github.nvim | 保存結果を案内し、編集画面の確定値を更新する。保存開始後の追記は未保存の変更として保持する。 |

代替フロー:

- A1: 全行を削除して保存すると、対象項目の全件を解除する。
- A2: 重複する同一値は1件として扱い、空行は値として送らない。
- A3: URIの末尾に`/assignees`または`/labels`を指定して同じ編集画面を開ける。
- A4: 編集を閉じる場合や再読み込みする場合は、未保存の変更を明示的に破棄するまで保持する。

例外フロー:

- E1: 存在しないラベルや割当できないユーザー名は理由を表示し、入力を保持する。入力だけを理由にラベルを新規作成しない。
- E2: 権限・通信などの保存失敗では、入力を保持して理由を案内する。
- E3: 現在の集合を欠けなく取得できない場合は理由を表示し、編集・保存を開始しない。既存の未保存の入力があれば保持する。

## API

GraphQL issueのassignees/labels connectionはpageInfo/endCursorで最後まで取得。assignableUsersとrepository labelsを対象repoで照合し、updateIssueのassigneeIdsまたはlabelIdsだけを指定する。空配列で全解除。DESIGN.md「GitHub API一覧」参照。

## エッジケースの決定

- 空: 全行削除は全解除。空行は値として送らない。
- 境界: 現在集合が複数ページでも欠けなく取得し、失敗時は保存を許さない。
- エラー: 無効名・権限不足・通信失敗の理由と入力を維持し、ラベルを新規作成しない。
- 並行: 保存時の対象repo・Issue・項目とsnapshotを固定し、追記を未保存として保つ。同一項目は最後にGitHubが受け付けた保存を正とする。
- 再表示: 更新後の確定値を表示し、未保存の追記は失わない。
