# Project項目のフィールド編集

- 種別: 機能設計書
- 対象 UC: UC-016 (docs/design/USECASES.md)
- 対象ストーリー: US-022

## 何を作るか

UC-016の利用者操作を実現する。対象規則はBR-072〜BR-077。ボードの状態と描画はprojects-board、float UIの共通規則はprojects-ui、APIはprojects-apiに従う。

## 入出力と振る舞い

### 起動と状態

- ボードで項目を選び`ghe`を実行すると、選択項目の編集可能なフィールドと現在値をfloatで表示する。空の列や列ヘッダを選んでいる場合は、項目を選ぶよう案内し、編集画面を開かない。
- 編集画面は`{board, item_id, fields, selected, loading, error, generation}`を保持する。`fields`はProjectのフィールド順を保ち、`dataType`が`TEXT`、`NUMBER`、`DATE`、`SINGLE_SELECT`のカスタムフィールドだけを含む。`TITLE`、`ASSIGNEES`、`LABELS`などの組み込みフィールドは含めない。
- 各行は`<name>  <current value>`とし、値がない場合は`未設定`とする。単一選択は選択肢名と色、テキストは文字列、数値は数値、日付は`YYYY-MM-DD`を表示する。現在値が未知の選択肢を指す場合は`不明 (<option_id>)`とする。
- 編集可能なフィールドがない場合は`No editable fields`を表示する。画面は開いたままとし、`q`/`<Esc>`で閉じる。
- `j`/`k`でフィールドを選び、`<CR>`で編集を開く。端では移動しない。`q`/`<Esc>`で編集画面を閉じ、ボードへ戻る。
- 編集画面はボードの子画面とし、ボードを閉じると編集画面と子画面も閉じる。同じボードで`ghe`を再度実行した場合は既存の編集画面を再利用し、選択項目に合わせて内容を更新する。

### 単一選択

- `<CR>`で選択肢の画面を開く。選択肢はフィールドの選択肢順に`● <name>`で表示し、現在値に印を付ける。末尾に`値を解除`を置く。
- `j`/`k`で選択肢を選び、`<CR>`で適用する。`q`/`<Esc>`で中止し、編集画面へ戻る。
- 選択肢を選んだ場合は`updateProjectV2ItemFieldValue`に`singleSelectOptionId`を渡す。`値を解除`は`clearProjectV2ItemFieldValue`を実行する。
- 成功したら選択肢の画面を閉じ、編集画面の現在値を更新する。ボードのモデルを更新し、編集したフィールドが`group_field`と同じ場合だけ、項目を新しい列（解除時は値なし列）へ移して再描画する。それ以外の単一選択は値を更新し、同じ列に留まる。選択は項目IDで維持し、移動後の列でその項目を選ぶ。同じ値の再選択はmutationを送らず、画面を閉じて現在値を維持する。
- 失敗したら選択肢の画面を閉じず、理由を表示して選択を保持する。ボードのモデルは変更しない。
- 現在値の選択肢がフィールドの選択肢にない場合でも、別の選択肢の適用と解除はできる。現在値の表示は`不明 (<option_id>)`とする。グループフィールドで未知の選択肢を指す項目は、ボードの値なし列に置く。

### テキスト・数値・日付

- `<CR>`で1行入力のfloatを開く。現在値を初期値とし、値がなければ空にする。プロンプトはフィールド名と種類（`Text`、`Number`、`Date`）をボーダーのタイトルに表示する。
- `<CR>`で適用、`<C-c>`で中止する。`<Esc>`は挿入モードを抜け、通常モードの`q`で中止する。
- 空の入力は解除として扱い、`clearProjectV2ItemFieldValue`を実行する。空でない場合は`updateProjectV2ItemFieldValue`に次の値を渡す。
  - テキスト: `{text=<入力>}`
  - 数値: `{number=<数値>}`
  - 日付: `{date="YYYY-MM-DD"}`
- 送信前に検証する。
  - 数値: `tonumber`で有限の数値になること。`nan`、`inf`、数値でない文字列は拒否する。小数・負数は許可する。
  - 日付: `YYYY-MM-DD`の形式で、実在する日付であること。年は0001〜9999とし、2026-02-30や2026-02-29（平年）は拒否する。
  - テキスト: 1行の文字列。改行は入力できない。長さのクライアント側上限は設けず、APIのエラーを表示する。
- 検証エラーは送信せず、理由を表示して入力と入力値を保持する。
- 成功したら入力の画面を閉じ、編集画面の現在値を更新する。ボードのモデルを更新して再描画する。テキスト・数値・日付の変更では列は変わらないため、選択は同じ列の同じ項目に維持する。
- 失敗したら入力の画面を閉じず、理由を表示して入力値を保持する。ボードのモデルは変更しない。

### 更新とローカル状態

- 更新は選択したフィールドだけを送り、他のフィールドを巻き戻さない。自動で再取得・再送しない。
- 成功時はmutationの応答でローカル状態を更新する。`group_field`を変更した単一選択では項目を新しい列へ移し、それ以外の単一選択は値を更新して同じ列に留まり、ボードを再描画する。編集画面の現在値も更新する。
- 失敗時は理由を表示し、ボードと編集中の入力を保持する。結果が不明な場合は成功と断定しない。
- 同じフィールドを続けて変更した場合は、最後に受け付けた値を表示する。他の利用者との同時編集はGitHubが最後に受け付けた値を正とし、クライアント側の競合解決は行わない。
- 項目が削除済み、または権限がない場合は理由を表示し、ボードを維持する。編集画面は開いたままとし、`q`で閉じられる。
- ボードを閉じた後や古い応答が届いた場合は、編集画面や別の画面を更新しない。

### 画面

- 編集画面は幅50%・高さ60%、選択肢は幅40%・高さ60%、1行入力は幅50%・高さ1とし、projects-uiの`target_size`と中央配置を使う。編集画面と選択肢はボードの子、入力は編集画面の子とする。
- 編集画面のヘッダに`Fields for #<number> <title>`を表示する。番号を持たない項目 (DraftIssue) は`Fields for <title>`、内容が非公開の項目は`Fields for [redacted]`とする。選択行を強調し、カーソルを選択行に置く。エラーがある場合はヘッダに理由を表示する。
- 選択肢のヘッダにフィールド名を表示する。現在値の行に印を付け、`値を解除`を末尾に置く。選択行を強調する。
- 1行入力はボーダーのタイトルにプロンプトを表示し、入力行に現在値を入れる。`startinsert`で開始し、カーソルを末尾に置く。
- 入力・選択肢の画面は`modifiable=true`、編集画面は`modifiable=false`とする。キーマップはバッファローカルに設定する。

### ヘルプと終了

- `q`/`<Esc>`で編集画面を閉じ、ボードへ戻る。選択肢・入力の`q`/`<C-c>`/`<Esc>`は編集画面へ戻る。
- ボードを閉じると編集画面と子画面を閉じる。ボードの`q`/`<Esc>`は編集画面を閉じた後にボードを閉じる。
- 編集画面のキー操作はボードのヘルプに含める。`?`はボードでのみ開く。

## API

`projects-api`のフィールド更新・解除を使う。単一選択は`updateProjectV2ItemFieldValue`の`value: {singleSelectOptionId: ...}`、解除は`clearProjectV2ItemFieldValue`を使う。テキスト・数値・日付は`value: {text|number|date: ...}`を渡す。フィールドの一覧と現在値はボードが取得済みのモデルを使い、追加のクエリを発行しない。mutationの応答は`projectV2Item {id}`であり、ローカル状態は送信した値で更新する。GraphQLの形はprojects-apiを参照する。

## 実装の配置

| 処理 | 層 | 実装先ファイル |
| --- | --- | --- |
| 編集画面・選択肢・入力・検証・ローカル更新 | 機能 | `lua/github/features/projects/field_edit.lua` |
| フィールド編集の振る舞いの検証 | テスト | `lua/github/features/projects/field_edit_spec.lua` |

ボードのモデル更新・列移動・選択・再描画はprojects-boardが提供するAPIを呼ぶ（`board.lua`は変更しない）。フィールド更新・解除のmutationはprojects-api、float・入力・選択肢の共通UIはprojects-uiの子が実装する。本issueは`field_edit.lua`と`field_edit_spec.lua`を所有する。編集画面はghを直接呼ばず、Projects API層を通す。テストではfake ghと`core/float.lua`を使い、実GitHubの書込みを行わない。`doc/github.txt`の`ghe`とフィールド編集のキー説明は実装issueで更新する。

## エッジケースの決定

- フィールド: 編集可能なフィールド0件、単一選択の選択肢0件、現在値なし、未知の選択肢、組み込みフィールドのみ。
- 単一選択: 別の選択肢、解除、選択肢の削除、同じ値の再選択、色の表示。
- テキスト: 空（解除）、日本語、長い文字列、改行を含む入力（1行のため不可）。
- 数値: 0、負数、小数、非常に大きい値、`nan`、`inf`、数値でない文字列、空（解除）。
- 日付: うるう年、平年の2月29日、存在しない日、年0、年9999、形式違い、空（解除）。
- エラー: 検証エラー、mutation失敗、項目の削除済み、権限なし、競合、レート制限、結果不明。
- 並行: 同じフィールドの連続変更、他の利用者との同時編集、古い応答、閉じた画面。
- 画面: 小さい画面、リサイズ、編集画面の再利用、ボードを閉じた場合、別タブの画面。
- 入力: 挿入モードの`<CR>`/`<C-c>`、通常モードの`q`、キャンセル、入力保持。
