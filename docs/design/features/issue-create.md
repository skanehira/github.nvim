# Issue作成

- 種別: 機能設計書
- 対象 UC: UC-003 (docs/design/USECASES.md)

## 何を作るか

UC-003の利用者操作を実現する。対象規則はBR-014, BR-015, BR-016, BR-017, BR-018, BR-019, BR-020。認証・実行・リポジトリ文脈と非同期の共通規約はDESIGN.md「横断規約」に従う。

## 入出力と振る舞い

- 一覧の`ghn`と`github://owner/repo/issues/new`から開始し、取得したMarkdownテンプレートとBlankを選ぶ。本文をMarkdown bufferで編集する。
- `:write`時に対象repoと送信時本文を固定し、本文を作業用一時ファイルに書いて `gh issue create -F <path> -R github.com/<owner>/<repo>` を端末で引数配列として起動する。作成中の再保存は処理中を通知し二重起動しない。
- 終了コードと所有する端末bufferの出力からURLを確認する。現在bufferが切り替わっても所有buffer IDを使う。確認された成功では編集・URLコピー・ブラウザ起動を選べる。追記がある場合は送信時のsnapshotだけを作成済みとし、その後の追記は未送信として残す。
- キャンセル・失敗・URL不明では本文を残して結果を案内し、自動再送しない。成功して追記がなければ本文・端末を閉じる。一時ファイルは使用後に削除する。

正常系の操作:

| # | アクター | アクション |
| --- | --- | --- |
| 1 | 開発者 | Issue一覧で`ghn`を実行するか、`:edit github://owner/repo/issues/new`で作成を開始する。 |
| 2 | github.nvim | 作成対象のリポジトリを保持し、利用できるMarkdownテンプレートと空の本文の選択肢を表示する。 |
| 3 | 開発者 | テンプレートまたは空の本文を選ぶ。 |
| 4 | github.nvim | 選択したテンプレートの本文、または空のMarkdown編集バッファを開く。 |
| 5 | 開発者 | 本文を編集し、`:write`を実行する。 |
| 6 | github.nvim | 本文と作成対象のリポジトリをghへ渡し、ghの対話画面を開く。 |
| 7 | 開発者 | ghの対話画面でタイトルなどを入力し、Issueの作成を完了する。 |
| 8 | github.nvim | 作成成功と作成先URLを確認して対話画面を閉じ、編集・URLコピー・ブラウザ起動の選択肢を表示する。作成開始後に本文の変更がなければ本文バッファも閉じ、変更があれば未送信の内容として残す。 |
| 9 | 開発者 | 次の操作を選ぶか、選択を終了する。 |

編集はUC-004、URLコピーはUC-011、ブラウザ起動はUC-010へ進む。次の操作を選ばずに終了しても、作成済みのIssueは維持される。

代替フロー:

#### A: 空の本文から作成する（ステップ3の代替）

| # | アクター | アクション |
| --- | --- | --- |
| 3a | 開発者 | 空の本文を選ぶ。テンプレートがないリポジトリでも、この選択肢を利用する。 |
| 3b | github.nvim | 空のMarkdown編集バッファを開く。 |

→ ステップ5へ進む。

#### B: テンプレートの選択をキャンセルする（ステップ3）

| # | アクター | アクション |
| --- | --- | --- |
| 3a | 開発者 | テンプレートの選択をキャンセルする。 |
| 3b | github.nvim | Issueを作成せずに選択を終了する。既存の編集中の内容を上書きしない。 |

→ 作成を終了する。

#### C: 作成処理中に再度保存する（ステップ6・7）

| # | アクター | アクション |
| --- | --- | --- |
| 6a | 開発者 | ghでの作成処理が完了する前に、同じ本文バッファで再度`:write`を実行する。 |
| 6b | github.nvim | 処理中であることを案内し、進行中の作成操作を継続する。追加の作成処理は開始しない。 |

→ ステップ7または8の完了を待つ。

#### D: 作成処理中に本文を編集する（ステップ6・7）

| # | アクター | アクション |
| --- | --- | --- |
| 6a | 開発者 | ghでの作成処理が完了する前に、元の本文バッファを編集する。 |
| 6b | github.nvim | 作成には送信開始時点の本文を使い、作成後もその後の編集を未送信の内容として保持する。自動で別のIssueを作成しない。 |

→ ステップ8へ進み、作成に使われた本文と未送信の編集を区別して案内する。

例外フロー:

#### E1: テンプレートを取得できない（ステップ2）

| # | アクター | アクション |
| --- | --- | --- |
| 2a | github.nvim | 権限・通信などの問題でテンプレートを取得できなかったことを認識する。 |
| 2b | github.nvim | 失敗理由を表示する。既存の入力済み本文がある場合は保持する。 |
| 2c | 開発者 | 状況を確認し、作成開始の操作をやり直す。 |

#### E2: 作成処理のキャンセル・失敗、または作成結果を確認できない（ステップ6〜8）

| # | アクター | アクション |
| --- | --- | --- |
| 6a | 開発者・gh | 対話処理をキャンセルするか、入力・権限・通信などの問題で作成処理を完了できない。作成先URLを確認できない場合もここで扱う。 |
| 6b | github.nvim | 入力済みの本文を保持し、キャンセル・失敗・結果未確認を区別して案内する。 |
| 6c | 開発者 | 結果を確認してから、本文の編集または次の操作を判断する。 |

作成結果が未確認の場合、Issueが作成されていないと断定しない。自動的に作成を再実行せず、開発者がGitHub側の結果を確認できるようにする。

## API

テンプレートはGraphQL repository.issueTemplatesのname/bodyを取得。作成はgh対話のサブコマンドを用いる。共通認証・外部実行はDESIGN.md「GitHub API一覧」「横断規約」。

## 実装の配置

| 処理 | 層 | 実装先ファイル |
| --- | --- | --- |
| Issue作成の状態・操作・表示 | 機能 | `lua/github/features/issues/create.lua` |
| Issue作成の振る舞いの検証 | テスト | `lua/github/features/issues/create_spec.lua` |

共通URI・プロセス・repo文脈の実装はfoundation設計に属し、操作固有コードは本機能が所有する。実行器・時刻・外界は注入する。各ファイルは実装時に作成する計画であり、現時点では存在しない。

## エッジケースの決定

- 空: テンプレートがなくてもBlankで作成できる。
- 境界: テンプレート取得に失敗した場合は理由を表示し、既存入力を保持する。
- エラー: 失敗・キャンセル・結果未確認を区別し、ghが非0でも作成済みの可能性を伝える。
- 並行: 同一bufferの多重作成を抑止し、終了後の追記を保持する。
- 再表示: 元一覧の再取得の成否と作成自体の成否を混同しない。
