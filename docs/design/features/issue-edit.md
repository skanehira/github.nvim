# Issueタイトル・本文編集

- 種別: 機能設計書
- 対象 UC: UC-004 (docs/design/USECASES.md)

## 何を作るか

UC-004の利用者操作を実現する。対象規則はBR-021, BR-022, BR-023, BR-024。認証・実行・リポジトリ文脈と非同期の共通規約はDESIGN.md「横断規約」に従う。

## 入出力と振る舞い

- 一覧の`ght`でカーソル行の1行タイトル、`ghe`または`github://owner/repo/issues/<number>`でMarkdown本文を開く。`ghe`は選択印があれば解除を案内する。
- 取得成功後だけ編集と保存を許し、初回取得失敗の空bufferを保存可能にしない。タイトルは空白だけ又は複数行を拒否し、本文は空を許す。
- 本文から`ght`・`ghm`・`gha`・`ghl`でタイトル・コメント一覧・担当者・ラベルへ進める。本文を開く際はedit/new/vnew/tabnewを選べる。タイトルは1行の横分割で開き、変更を保存できたら閉じる。送信後に追記があれば閉じず保持する。
- 未変更の既存本文・タイトルの`:write`は送信しない。変更済みの`:write`は対象項目だけを更新する。タイトル更新に本文を含めず、本文更新にタイトルを含めない。応答待ちに追記された内容は未保存として残し、失敗時は全入力を維持する。

同一編集bufferの保存中に再度`:write`した場合は進行中と通知し、追加の保存要求を送らない。保存開始後の編集は未保存のまま残し、完了後に利用者が改めて保存できる。

正常系の操作:

| # | アクター | アクション |
| --- | --- | --- |
| 1 | 開発者 | 一覧の`ght`でカーソル行のタイトル、`ghe`または`github://owner/repo/issues/<number>`で本文を開く。 |
| 2 | github.nvim | 現在の対象項目を取得し、タイトルは1行、本文はMarkdownとして表示する。 |
| 3 | 開発者 | 内容を編集して`:write`を実行する。 |
| 4 | github.nvim | 入力を検証し、対象リポジトリ・Issue・項目を固定してgh経由で保存する。 |
| 5 | github.nvim | 成功したことを案内する。保存開始後にも追記があれば、その追記は未保存の変更として残す。 |

代替フロー:

- A1: 本文を空にして保存した場合は、本文を空に更新する。
- A2: 本文編集の`ghe`は選択印がある場合に解除を案内する。タイトル編集はカーソル行の1件を対象にする。
- A3: 編集を閉じる際、未保存の変更はNeovimの通常の破棄操作で明示的に捨てた場合だけ破棄する。

例外フロー:

- E1: 空または複数行のタイトルは理由を表示し、入力内容を保持して保存を開始しない。
- E2: 権限・対象の不存在・通信などで保存が失敗した場合、理由を表示して編集内容を保持する。
- E3: 編集開始時の取得に失敗した場合は理由を表示し、取得できなかった項目を空の現在値として保存可能にしない。既存の未保存の入力があれば保持する。

## API

GraphQL issue(number)で対象ID・title・bodyを取得し、updateIssueのinputにidと変更項目だけを渡す。認証・エラー・同時編集の共通方針はDESIGN.md「横断規約」参照。

## エッジケースの決定

- 空: 空タイトルは拒否、空本文は保存できる。
- 境界: タイトルは1行。本文はUTF-8と改行を保持する。
- エラー: 取得失敗で空の上書きを防ぎ、保存失敗で編集内容を維持する。
- 並行: GitHubが最後に受け付けた同一項目の保存を正とし、保存開始後の追記は未保存とする。
- 再表示: 未保存の変更を明示的な破棄なく再取得結果で置き換えない。
