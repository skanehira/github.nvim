# github.nvim ユーザーストーリー

- 種別: ユーザーストーリー
- プロダクトモード: cli（Neovim内のコマンド・バッファ操作）
- 設計ループ: フルコース
- 作成日: 2026-10-28

## 目的と合意済みの範囲

denops-gh.vimの実装済み機能を、Neovim向けLuaプラグインgithub.nvimへ移植する。NeovimからIssueの確認・更新・会話を行い、編集中の作業からGitHubへ移る負担を減らす。

初期版には移植元の実装済み機能のうち入力補完を除く機能を含め、Mustとする。補完機能は今回不要という利用者の指示に基づき対象外とする。操作体験は移植元の専用バッファとキーマップを基本にする。公開URIのスキームには`github://`を使う。lazy.nvimはLuaの構成・実装方式の参考にし、画面をlazy.nvim風へ変更する要件は含めない。

機能を引き継ぐことと、移植元の取得上限や不具合をそのまま引き継ぐことは区別する。表示件数、異常時の挙動、公開インターフェースの互換範囲はユースケース・技術検証・設計で具体化する。本書はユーザーができることを定める。

## 将来の統合とGitHub通信の設計条件

将来、次のプラグインの機能をgithub.nvimへ統合する。

| 統合元 | 統合する機能領域 | 今回の扱い |
| --- | --- | --- |
| github-actions.nvim | Actionsのバージョン確認、実行、履歴、ログ、監視など | 共通基盤の設計条件として参照し、機能移植は将来行う。 |
| review.nvim | ローカル差分・PRのレビュー、コメント下書き、レビューセッションなど | 共通基盤の設計条件として参照し、機能移植は将来行う。 |

初期版の16件のストーリーと、合意済みの12件のユースケースの範囲を維持する。以下の条件を、ユースケース、実現可能性検証、横断設計、機能設計へ引き継ぐ。

1. **GitHub通信はghを使う。** denops-gh.vim由来の機能を含め、GitHub APIの呼び出しは`gh api`を利用する。RESTとGraphQLの両方を対象とし、認証情報の取得・管理はghに委ねる。対話を伴うIssue作成などのghサブコマンドも、共通の外部コマンド実行処理を通す。
2. **機能別に初期化・設定・状態を分ける。** Issue、Actions、レビューを独立した機能領域として扱う。GitHub通信に必要なghの導入・認証確認は、その機能を利用する時点で行う。将来のローカル差分レビューは、GitHub認証なしで利用できる性質を保つ。
3. **GitHub上の対象とローカルの作業場所を区別する。** ホスト・owner・repoによる識別と、ローカルリポジトリ・worktree・操作開始時の作業ディレクトリを別に扱う。画面を開いた後のディレクトリ変更や、別機能のworktree操作で通信先が変わらないようにする。
4. **共通部と機能固有の処理を分ける。** 外部コマンド実行、GitHub通信、リポジトリ識別など、実際に共有する処理の境界を定める。画面の形、操作ごとのエラー解釈、コメントのデータと送信時点は、各機能が管理する。
5. **画面・非同期処理・キャッシュの所有者を明確にする。** 状態は機能と対象リポジトリを識別して保持する。読み込み中の状態や選択状態は画面ごとに持ち、古い応答や画面を閉じた後の応答が、別の機能・画面を更新しないようにする。窓・バッファ・装飾・設定の後始末も、各機能が所有する範囲で行う。
6. **依存と保存データを機能単位で扱う。** Issue機能を使うために、ActionsのYAML解析や任意の選択UIの依存を要求しない。レビューの下書き・永続セッション・worktreeはレビュー機能が管理する。既存review.nvimの保存先や旧コマンドを引き継ぐ方法は、将来の統合時に具体化する。

公開コマンド、Lua API、設定キー、既存データの移行方法、Actions・レビュー固有の画面は、それぞれの機能を統合する際に設計する。共通部の初期実装範囲は、今回のIssue移植で利用する処理から決める。

| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| Issue一覧を開く                           | `:edit github://owner/repo/issues`。対応するGitHubのHTTPS URLからも開く。                                                                                          | US-002                         |
| Issueの検索・編集・作成・開閉             | `ghs`、`ghe`、`ght`、`ghn`、`gho`、`ghc`。編集は`:write`で反映する。                                                                                           | US-003、US-005〜US-008         |

| コメントを読む・投稿・編集する            | `ghm`で一覧を開き、`ghn`で投稿、`ghe`で編集する。移植元のコメントを指定するURIも後続設計で整理する。                                                           | US-011〜US-013                 |
